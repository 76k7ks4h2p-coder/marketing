# 権限・RLS の検証手順

このディレクトリには、Supabase の Row Level Security（RLS）とアプリ側の権限制御を
確認するための手段をまとめています。

CI で自動実行できるのは `tests/security/*.test.ts`（SQL の静的検証）までです。
実際の DB 挙動の確認には、稼働中の Postgres が必要です。以下の手順で確認してください。

---

## 1. SQL による自動検証（推奨・ローカル Supabase が必要）

`rls-verification.sql` は 37 項目の権限チェックを 1 ファイルで実行します。
最後に `ROLLBACK` するため、データは残りません。

```bash
# 1. ローカル Supabase を起動
pnpm dlx supabase start

# 2. マイグレーションと seed を適用
pnpm dlx supabase db reset

# 3. 接続 URL を取得して検証スクリプトを実行
DB_URL=$(pnpm dlx supabase status -o env | grep '^DB_URL=' | cut -d= -f2- | tr -d '"')
psql "$DB_URL" -v ON_ERROR_STOP=1 -f tests/rls/rls-verification.sql
```

成功すると各項目に `OK n: ...` が出力され、最後に `ALL RLS CHECKS PASSED` が表示されます。
いずれかが失敗すると `FAILED: ...` の例外で停止します。

> ⚠️ このスクリプトは `auth.users` へ直接 INSERT します。**ローカル開発環境専用**です。
> 本番データベースでは絶対に実行しないでください。

## 2. 静的検証（DB 不要・`pnpm test` に含まれる）

```bash
pnpm test
```

- `tests/security/rls-migration.test.ts`
  マイグレーション SQL を読み込み、RLS の有効化・各ポリシーの条件・
  `SECURITY DEFINER` 関数の `search_path` 固定・Storage パス検証などが
  消えていないことを検証します。

- `tests/security/owner-columns.test.ts`
  オーナー向けの `SELECT` 列に `admin_notes` が含まれないこと、
  ワイルドカード（`*`）を使っていないことを検証します。

### admin_notes についての補足

RLS は **行単位** の制御であり、列単位の制御はできません。
そのため `service_requests` の `admin_notes` は、DB レベルでは
オーナー本人の行に対して読み取り可能です。

オーナーへ返さないようにしているのは **アプリケーション層** です。

- 列を明示した `OWNER_REQUEST_COLUMNS` / `OWNER_REQUEST_LIST_COLUMNS`
  （`src/lib/queries/columns.ts`）だけをオーナー向け取得処理で使用する
- オーナー向けの型 `OwnerRequest`（`src/lib/queries/owner.ts`）に
  `admin_notes` を含めない（型レベルでも渡せないようにする）
- 上記が壊れていないことを `tests/security/owner-columns.test.ts` で検証する

## 3. 画面からの手動テスト手順

外部サービス（Supabase / Resend）の認証情報が必要なため、以下は手動で確認します。

### 事前準備

1. `.env.local` に Supabase の URL と Publishable Key を設定する
2. `pnpm dlx supabase db reset`（ローカル）または `supabase db push`（リモート）
3. `pnpm dev` で開発サーバーを起動
4. `/signup` から **3 アカウント** を登録する
   - オーナー A（例: `owner-a@example.com`）
   - オーナー B（例: `owner-b@example.com`）
   - 管理者（例: `admin@example.com`）
5. 管理者に admin を付与する（Supabase SQL Editor）

   ```sql
   update public.profiles
   set role = 'admin'
   where id = '対象ユーザーUUID';
   ```

### T1. 未ログインでのアクセス制御

| 手順                                                        | 期待結果                                                                                           |
| ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| ログアウト状態で `/dashboard` を開く                        | `/login?redirectTo=/dashboard&reason=unauthenticated` へ遷移し、「ログインが必要です」と表示される |
| 同様に `/properties` `/requests` `/profile` `/admin` を開く | いずれもログイン画面へ遷移する                                                                     |
| ログイン後                                                  | 元のページへ戻る                                                                                   |

### T2. owner が /admin へアクセスできない

| 手順                                        | 期待結果                                                                                         |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| オーナー A でログインし `/admin` を開く     | `/dashboard?denied=admin` へ遷移し、「管理画面へのアクセス権限がありません」と日本語で表示される |
| `/admin/requests` `/admin/providers` も同様 | いずれもダッシュボードへ戻る                                                                     |

### T3. 他人の URL への直接アクセス

| 手順                                                                   | 期待結果               |
| ---------------------------------------------------------------------- | ---------------------- |
| オーナー A で物件を作成し、URL の `id` を控える                        | —                      |
| オーナー B でログインし、その URL（`/properties/<A の物件 id>`）を開く | 404 ページが表示される |
| 同様に `/requests/<A の案件 id>` を開く                                | 404 ページが表示される |

> 「権限がありません」ではなく 404 にしているのは、データの存在有無を漏らさないためです。

### T4. 対応エリア外の物件

| 手順                                                      | 期待結果                                                         |
| --------------------------------------------------------- | ---------------------------------------------------------------- |
| `/properties/new` を開く                                  | 都道府県「広島県」・市区町村「福山市」が読み取り専用で表示される |
| DevTools で hidden の `city` を「広島市」に書き換えて送信 | サーバー側の Zod 検証で拒否され、日本語のエラーが表示される      |

### T5. 見積もりの公開前後

| 手順                                                                          | 期待結果                                                                             |
| ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 管理者が見積もりを `draft` で登録する                                         | オーナーの依頼詳細には「現在、内容を確認し、見積もりを取得しています。」と表示される |
| 管理者が「オーナーへ公開する」を押す                                          | オーナー画面に見積もりカードが表示される                                             |
| 公開済み見積もりが 0 件の状態でステータスを「見積もり確認待ち」にしようとする | 選択肢が無効化され、サーバー側でも拒否される                                         |

### T6. 見積もりの二重選択

| 手順                                                       | 期待結果                                                                                           |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| オーナーが「この業者を選ぶ」を押す                         | 確認ダイアログに「この見積もりを選択します。選択後の変更は運営者への連絡が必要です。」と表示される |
| 確定する                                                   | ステータスが「業者選択済み」になり、他の見積もりの選択ボタンが消える                               |
| ブラウザの戻るボタンで戻り、別の見積もりを選択しようとする | 選択ボタンが表示されない。仮に POST しても DB 関数が `ALREADY_SELECTED` で拒否する                 |

### T7. ファイルアップロード

| 手順                                          | 期待結果                                                   |
| --------------------------------------------- | ---------------------------------------------------------- |
| 6 枚目の写真を追加しようとする                | 「アップロードできるファイルは5件までです。」と表示される  |
| 10MB を超えるファイルを選択する               | 「ファイルサイズが10MBを超えています。」と表示される       |
| `.gif` や `.svg` を選択する                   | 「対応していない形式です。」と表示される                   |
| `.pdf` の中身を `.png` にリネームして選択する | 「ファイルの種類と拡張子が一致していません。」と表示される |
| アップロードした写真を開く                    | 署名付き URL（`token=` を含む）で表示される                |
| 署名付き URL の `token` を書き換えて開く      | 表示できない（バケットが非公開のため）                     |

### T8. 完了報告

| 手順                                           | 期待結果                                                                          |
| ---------------------------------------------- | --------------------------------------------------------------------------------- |
| 管理者が完了報告を登録する（「完了へ変更」ON） | ステータスが「完了」になる                                                        |
| 管理者が完了写真を登録する                     | オーナーの依頼詳細に完了報告と完了写真が表示される                                |
| オーナーが完了写真をアップロードしようとする   | オーナー画面に完了写真のアップロード UI は無い。API を直接叩いても RLS が拒否する |

### T9. メール通知（Resend 未設定時）

| 手順                                         | 期待結果                                                                                     |
| -------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `RESEND_API_KEY` を未設定にする              | —                                                                                            |
| 依頼を作成する                               | 処理は成功し、サーバーログに「メール通知はスキップされました」と宛先・件名・本文が出力される |
| 見積もりを公開する / 選択する / 完了登録する | いずれも処理は成功し、通知内容がログに出力される                                             |
