# Tachibana Campus Navi

京都橘大学の教室番号（例: `H301`）を入力するだけで、その教室が **どの建物の何階にあるか** をすぐに確認できる Web アプリです。スマートフォンでの利用を第一に作っています。

> [!IMPORTANT]
> **京都橘大学の公式サービスではなく、大学による認定・承認も受けていません（学生制作の β 版）。**
> 授業の教室は、必ず大学のポータルサイト（時間割）や掲示もあわせて確認してください。

- 対象: 京都橘大学（京都府京都市山科区大宅山田町34）
- データの基準日: 2026年10月18日
- 技術: React 19 / TypeScript 5.9 / Vite 7 / Tailwind CSS 4 / Vitest 4（実行時の依存は React と ReactDOM のみ）

## できること

| 機能                       | 内容                                                                                                                                                                                                                                  |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **教室番号検索**（最重要） | 画面上部の検索バーに入力すると、入力途中から候補を表示。`H301` → 「H301教室／アカデミックリンクス・3階」。全角・小文字・ハイフン・空白・「教室」付き（`ｈ－３０１教室`）や O/0 の打ち間違い（`G0O1`）も吸収                           |
| 検索結果の表示             | 教室番号・建物名・建物番号・階数・収容人数・地図上の位置・確認状況・出典、「地図で見る」「ここへ行く」ボタン                                                                                                                          |
| 見つからない番号の案内     | `Z999` →「見つかりません」。`F404` のように建物は分かるが公式一覧にない番号は、「番号の規則では響友館（F）の4階にあたるが、公式一覧に掲載がないため確認できない」と**未確認であることを明示**して案内                                 |
| 建物・階別の教室一覧       | 建物を選ぶと階が並び（B1・1F・2F…）、階を選ぶとその階の教室と施設を表示                                                                                                                                                               |
| 建物名・施設検索           | 「清和」「みかん」「H棟」「食堂」「図書館」「コモンズ」「書道」「Media Lab」「清和館3階」「H棟 4F」なども検索可                                                                                                                       |
| キャンパスマップ           | 建物の位置が登録されると SVG の概略図（ピンチ／ホイールで拡大縮小、ドラッグで移動、建物の選択・強調、選んだ教室の建物へ自動で移動）を表示。**現在は位置データが未登録のため、実際の配置ではないことを明示した建物一覧を表示**（後述） |
| 経路案内                   | 出発地（門・交通／主要施設／建物／教室）と目的地を選んで探索。公式資料と照合済みの通路だけを使う Dijkstra 法。**検証済みの通路データがない現在は、道順を出さずに「建物と階の案内」と「必要な追加データ」を表示**                      |
| バリアフリー案内           | 「階段・段差を避ける」を選ぶと、段差なしが確認された区間だけで探索。データがない現在は安全な経路を保証しない旨と、公式バリアフリーマップ（2026年10月版）への導線を表示                                                                |
| お気に入り・最近の検索     | 端末内（localStorage）に保存。ページを読み込み直しても残る。保存できない環境では、その旨を表示してメモリ上で動作                                                                                                                      |
| 共有 URL                   | `?room=H301`／`?building=academic-terrace`／`?facility=main-gate` を開くと、その教室・建物・施設を表示。共有ボタン（Web Share API／リンクのコピー）                                                                                   |
| PWA                        | ホーム画面に追加でき、一度開けばオフラインでも教室検索と共有 URL が使える（Service Worker）                                                                                                                                           |
| その他                     | ダークモード、PC 向けの 2 カラム表示、ブラウザの「戻る」で詳細を閉じる、キーボード操作・スクリーンリーダー対応                                                                                                                        |
| 配置エディタ（保守用）     | `editor.html`。公式キャンパスマップの画像を端末内だけで下図にして、建物の範囲をドラッグで登録し、JSON に書き出す                                                                                                                      |

### 画面構成（スマートフォン）

- 上部: アプリ名と教室検索バー
- 中央: キャンパスマップ（位置データがない間は建物一覧）
- 下部: 選んだ教室・建物の詳細を表示するボトムシート（つまみのドラッグ／タップで大きさを変更）
- 下部ナビゲーション: 「マップ」「検索」「お気に入り」

PC（幅 1024px 以上）では、左に検索と詳細、右に地図を並べます。

## ローカルでの起動手順

必要なもの: **Node.js 22.18 以上**（`scripts/*.ts` を Node で直接実行するため）、**pnpm 10**

```bash
cd tachibana-campus-navi
pnpm install
pnpm dev            # http://localhost:5173/ （配置エディタは /editor.html）
```

本番用のビルドと確認:

```bash
pnpm build          # dist/ に出力（静的ファイルのみ。任意のサブパスに置ける）
pnpm preview        # http://localhost:4173/
```

`dist/` をそのまま静的ホスティング（GitHub Pages・Cloudflare Pages・学内 Web サーバーなど）に置けば公開できます。サーバー側の処理やデータベースは不要です。

### コマンド一覧

| コマンド                                             | 内容                                                                                                                        |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `pnpm dev`                                           | データを生成して開発サーバーを起動                                                                                          |
| `pnpm build`                                         | データ生成 → 型チェック → 本番ビルド（Service Worker を自動生成）                                                           |
| `pnpm build:standalone`                              | データまで埋め込んだ単体 HTML（`dist-standalone/tachibana-campus-navi.html`）を作る。サーバーなしで開けるプレビュー・配布用 |
| `pnpm test`                                          | 自動テスト（Vitest）                                                                                                        |
| `pnpm typecheck` / `pnpm lint` / `pnpm format:check` | 型・ESLint・Prettier                                                                                                        |
| `pnpm data:build`                                    | `data/rooms.csv` から `public/data/rooms.json` を生成し、全データの整合性を検査                                             |
| `pnpm data:check`                                    | 生成済みの JSON が CSV と一致しているか、整合性に問題がないかだけを確認（CI 向け）                                          |
| `pnpm smoke <URL> [保存先]`                          | 実ブラウザでのスモークテスト（Playwright がある環境で。依存には含めていない）                                               |
| `pnpm icons`                                         | `public/icons/icon.svg` から PWA 用 PNG を作り直す（Playwright を使用）                                                     |

### 確認状況の区分

すべての建物・教室・施設・配置・通路に、確認状況と出典を持たせています。

| 区分         | 意味                                                             | 画面表示                                                           |
| ------------ | ---------------------------------------------------------------- | ------------------------------------------------------------------ |
| `verified`   | 公式資料と照合済み                                               | 「照合済み」（緑）                                                 |
| `pending`    | 公式資料に掲載されている情報だが、原本との最終照合が済んでいない | 「照合待ち」（黄）＋時間割もあわせて確認するよう案内               |
| `unverified` | 根拠を確認できていない                                           | 「未確認」。経路案内には一切使わない（現在のデータには存在しない） |

### 取得経路と制約（重要）

開発環境のネットワーク制限で、`www.tachibana-u.ac.jp` と `cai6.tachibana-u.ac.jp` に直接アクセスできませんでした（接続が拒否され、URL 取得ツールも名前解決できない状態）。そのため:

- **教室一覧**は、検索エンジンの索引に含まれる公式ページ「キャンパスマップ／教室一覧」の本文（建物・階ごとの表の行）から転記しました。建物・階ごとに複数回照会し、すべての教室で「番号の階＝表の階」が一致することを自動テストで確認しています。それでも原本との照合ではないため、開発指示書 §8 の 6 教室（索引の内容とも一致）以外は「照合待ち」としています。
- **建物の配置（地図画像）・バリアフリーマップ PDF の中身**は取得できなかったため、位置・通路・設備は登録していません（推測で埋めていません）。
- 公式一覧の表記で判断が必要だった点は、各教室の備考（`note`）に残しています（例: 清香館 B101〜B110 は範囲表記で各室の収容数は未確認、児優館は見出しが C201〜C504 だが 5 階の表には C502 のみ、明優館 D301 の教室名は要確認）。

### データの更新手順

1. **教室**: `data/rooms.csv` を編集（列: `code, building_id, floor, name, capacity, status, source_id, checked_at, note`。地下1階は `-1`、収容人数「ー」は空欄）
2. `pnpm data:build` を実行 → 番号の規則と階の食い違い、存在しない建物・出典への参照、重複などがあればエラーで止まる
3. `pnpm test` を実行して公開
4. **建物・施設・経路**: `public/data/*.json` を編集（形式は `src/domain/types.ts`）。差し替えるだけで再ビルドなしに反映され、Service Worker もデータはネットワーク優先で取り直す
5. **建物の位置**: 配置エディタ（`/editor.html`）で公式キャンパスマップの画像を下図に読み込み、建物をドラッグで配置 → 書き出した `buildings.json`・`facilities.json`・`meta.json` で置き換える。照合済みとして書き出さなかった配置は地図上で破線（照合待ち）になる
6. **通路**: `route-graph.json` にノード（門・入口・エレベーター・階段など）とエッジ（距離・通行可否・段差の有無・勾配・出典）を追加。`status: "verified"` かつ `passable: true` のエッジだけが経路探索に使われる

## 設計上の判断

- **推測しない**: 位置・通路・設備は、公式資料で確認できるまで `null`／空のまま。番号の規則から読み取れる階は「未確認」と明示した案内にだけ使い、教室として登録しない。経路は `verified` かつ通行可能なエッジだけで探索し、組めなければ不足データを返す
- **表示データとロジックの分離**: データは `public/data/*.json`（教室の正本は CSV）、ロジックは `src/domain/`（React に依存しない純粋関数）。データだけを差し替えれば再ビルドなしで更新できる
- **壊れない**: 取得したデータは実行時に検証し、不正なレコードだけを除外。教室・建物以外のファイル取得に失敗しても検索は使える。端末保存ができない環境でもメモリ上で動作
- **依存を増やさない**: 実行時の依存は React と ReactDOM のみ。アイコンはインライン SVG、CSV パーサ・Service Worker・地図のパン／ズームも自前の小さな実装
- **既存リポジトリとの関係**: このリポジトリはプロジェクトごとにブランチを分けて運用されているため、既存の OwnerBase（Next.js）とは独立したサブプロジェクトとして追加し、ルートの TypeScript・ESLint・Prettier の対象から外している
- **プライバシー**: ログイン不要。個人情報・位置情報は収集せず、外部送信もしない（解析ツールなし）
